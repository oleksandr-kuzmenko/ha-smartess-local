# SmartESS Local

Local Home Assistant monitoring for **Aninerel / ANENJI and other compatible
SmartESS inverters**, using the standard Eybond / SmartESS Wi-Fi dongle. Battery percentage, mains
presence, operating mode, and power graphs without vendor-cloud polling.

## Tested hardware and scope

The `smartess-local` library was tested on the owner's **Aninerel / ANENJI**
installation using the original Wi-Fi dongle, with no firmware changes:

- Battery percentage readings and their changes matched the inverter display.
- Mains loss was reflected by 0 V input and `OFF_GRID` mode.
- After mains returned, input voltage returned before the switch to `MAINS`.
- Battery discharge and load changes were observed with a water heater running.

This is evidence for this particular installation, not a claim that every
Aninerel / ANENJI model or firmware works. Other SmartESS dongles may use a
different inverter protocol, including PI17. This integration uses the
holding-register protocol implemented by `smartess-local`.

Integration tests run against Home Assistant Core **2026.10.0**. Installation
and end-to-end operation of this custom integration on HA OS are still pending.
The initial version supports one inverter and is read-only.

## Installation

Install through [HACS](https://www.hacs.xyz/docs/use/download/download/):

1. Open **HACS → menu → Custom repositories**.
2. Add `https://github.com/oleksandr-kuzmenko/ha-smartess-local` as an **Integration**.
3. Download **SmartESS Local** and restart Home Assistant.
4. Open **Settings → Devices & services → Add integration → SmartESS Local**.
5. Enter the inverter dongle IP and Home Assistant's LAN IP address.

This repository is installed as a custom repository, not through the default
HACS catalog. Stop other local clients polling the dongle before setup.

## Network requirements

The integration domain is `smartess_local`.

The dongle must reach Home Assistant on **TCP 8899**; Home Assistant must reach
it on **UDP 58899**. Different subnets work if routing and firewall rules allow
both directions. Port 8899 must be free. No MQTT broker or separate service
is needed. Settings can be changed through the integration's **Reconfigure**
action; entity IDs are preserved. Reconfiguration reloads the connection, and
HA retries if the new address cannot be reached.

The library is pinned in `manifest.json` to an immutable GitHub source archive.
Home Assistant installs it automatically; no submodule or local checkout is
needed on HA OS. Installation needs internet access to download the dependency;
subsequent inverter polling is local. PyPI publication is not currently verified,
so this integration does not depend on a presumed PyPI release.

## Entities

Entity IDs are generated by Home Assistant and can be renamed. These keys are
stable identifiers within the integration. All entities become `unavailable`
after a failed poll; missing data never means zero charge or absent mains.

| Key | Type and values | Meaning |
| --- | --- | --- |
| `grid_present` | Boolean; HA `on` / `off` | `on` when measured grid voltage is greater than 50 V. Presence only, not a guarantee that the inverter accepts the grid. |
| `battery_percentage` | Integer, 0–100 % | Charge reported by the inverter, not a calculated capacity estimate. |
| `working_mode` | Enum: `power_on`, `standby`, `mains`, `off_grid`, `bypass`, `charging`, `fault` | Operating mode reported by the inverter. |
| `battery_discharging` | Boolean; HA `on` / `off` | `on` when average battery current is below −0.5 A. The fixed deadband ignores tiny negative readings near zero. |
| `output_power` | Integer, W | Active output power. Expected to be nonnegative; upper limit depends on the inverter. |
| `battery_power` | Signed integer, W | Negative: discharge; positive: charge; zero: no measured battery power. |
| `battery_voltage` | Decimal, V | Measured battery voltage; expected nonnegative, range depends on the battery. |
| `grid_voltage` | Decimal, V | Measured input voltage; 0 V when absent in the tested system. |

The 50 V and −0.5 A thresholds are integration choices, not vendor status bits
or configurable protection limits. `off_grid` does not imply battery discharge:
solar generation may supply the load. Conversely, when mains returns the
inverter can continue discharging while it waits before switching to `mains`.

Numeric sensors provide measurement statistics for ordinary history graphs.
They are not cumulative kWh meters for the Energy dashboard. No automatic
load switching, battery thresholds, inverter setting changes, or estimated
runtime are included. Configure household automations separately in HA and
check entity availability before acting.

## Connection behavior

One persistent library connection supplies all entities every 10 seconds.
After a failed read it is closed, the entities become unavailable, and the
coordinator reconnects on a subsequent scheduled update. Initial failures use
Home Assistant's setup retry mechanism. One full connect/read attempt is
limited to 15 seconds. This is polling, not instantaneous outage detection.
Unloading the integration or stopping HA closes its connection.

A cached reading is retained internally for diagnostics but is not advertised
as currently available after failure. Invalid battery percentages outside
0–100 reject the update. Normal logs report failures and recovery; raw readings
are only emitted by the library at DEBUG, apart from its first-frame INFO log.

## Development

```bash
uv sync
uv run pytest
uv run ruff check custom_components tests
```

Tests use real Home Assistant 2026.10.0 with the library boundary replaced by a
fake inverter. They cover configuration, all eight entities, unavailable/recovery,
connection reuse, shutdown, cancellation, reconfiguration, and sensor thresholds.
The separate library repository owns wire-format and localhost socket tests.

To test local library changes, install its checkout into the development venv;
keep the manifest pinned to a published version or immutable source revision
before distributing an integration update. There are no Git submodules.
